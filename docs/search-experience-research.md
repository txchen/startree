# Search Experience Research: Pinterest, Pintree, and PintreeNewTab

Research date: 2026-08-19
Scope: product identity, search entry, scope, suggestions and results, keyboard behavior, and navigation efficiency relative to the current StarTree workspace.

## Conclusion

The direct new-tab reference is **PintreeNewTab**, an independently published open-source extension based on Pintree. It is not Pinterest, and it is not the official Pintree browser extension.

- **Pinterest** is a visual discovery product. Its search is optimized for discovering and progressively refining ideas, not for retrieving browser bookmarks.
- **Pintree** at `pintree.io` is a bookmark-to-directory website product. Its official repository describes bookmark search and links `demo.pintree.io` as its demo ([source](https://github.com/Pintree-io/pintree/blob/91023a3664d3ae9450acbc63eae9134f95b8d383/README.md#L7-L31)).
- **PintreeNewTab** is a separate project “based on Pintree,” explicitly designed to present browser bookmarks as a new-tab-style navigation page. Its README links the relevant [Chrome Web Store listing](https://chromewebstore.google.com/detail/ekfkalhnkifkoijcioheanlegfgcgnee), which is offered by `qaqtangxiaoqi`, not Pintree or Pinterest ([source](https://github.com/tangxiaoqi-tangxiao/PintreeNewTab/blob/cf4f8915ebe81d49bc132999bdf1b8a2547ecd82/README_en.md#L1-L35)).
- Pintree's official Chrome extension is instead **Pintree Bookmarks Exporter**, whose package describes JSON export rather than a new-tab UI ([source](https://github.com/Pintree-io/bookmarks-exporter/blob/fa38e1f65d94247fb20bbd56701088b22e83b808/package.json#L1-L7), [store listing](https://chromewebstore.google.com/detail/pintree-bookmarks-exporte/mjcglnkikjidokobpfdcdmcnfdicojce)).

One further nuance: PintreeNewTab's current background source opens its page in a newly created tab when the extension action is clicked; it does not declare an automatic browser new-tab override in the reviewed source ([source](https://github.com/tangxiaoqi-tangxiao/PintreeNewTab/blob/cf4f8915ebe81d49bc132999bdf1b8a2547ecd82/src/entrypoints/background/index.ts#L1-L13)). “NewTab” therefore describes the experience and destination more than an automatic replacement mechanism in this revision.

## Implications for StarTree

StarTree's current search is already more efficient than PintreeNewTab for known-item retrieval. It searches more useful fields, includes folders, responds as the user types, exposes location context, and supports a complete keyboard loop. Preserve those advantages.

Recommended direction:

1. **Keep one bookmark-search mode.** Do not copy Pintree's always-visible `Bookmarks / Web / AI` mode tabs. Browser web search already has a highly efficient entry point in the address bar, while the extra modes increase visual weight and decision cost.
2. **Keep global search as the default scope.** Pintree's all/current toggle can help very large libraries, but it should be an optional compact filter rather than a required choice. Folder paths in StarTree's results already disambiguate global matches.
3. **Keep live overlay results.** Replacing the entire grid after Enter, as PintreeNewTab does, destroys browsing context and adds a return step. The current overlay is faster for quick navigation.
4. **Use Pinterest ideas only for discovery features.** Recent searches, suggested queries, and guided refinements are valuable when users do not know what they want. They are unnecessary for the primary known-bookmark path and would introduce history/privacy concerns.
5. **Make result activation semantics explicit.** A useful next refinement would be a documented keyboard/mouse convention for same-tab versus new-tab opening, for example `Enter` versus `Cmd/Ctrl+Enter`. This is a recommendation, not behavior established by the reviewed references.
6. **Retain a compact visual footprint.** Pintree's focused 8rem editor is appropriate for AI prompts, not bookmark lookup. StarTree should keep the search control one line high and spend vertical space on results only when results exist.

## Targeted gaps in the current implementation

These are improvements to StarTree's existing retrieval model, not features to copy wholesale from Pintree.

1. **Explain non-title matches.** The index searches URL, Tags, and Note, but each result row renders only the title and Folder path ([index fields](../src/client/bookmarks/bookmark-search.ts#L35-L51), [result markup](../src/client/bookmarks/BookmarksPage.vue#L828-L863)). A compact domain, matching Tag, or Note excerpt would explain why a result appeared and help distinguish similarly titled Bookmarks.
2. **Bound the result overlay.** The adapter returns every MiniSearch match and the component renders every result, while only the container's visual height is capped ([search adapter](../src/client/bookmarks/bookmark-search.ts#L151-L167), [overlay styles](../src/client/app/styles.css#L433-L449)). Broad prefixes in a large library can therefore create a large hidden DOM. Return a small ranked window, with an explicit count or a secondary full-results action if that becomes necessary.
3. **Complete combobox semantics.** The input exposes `role="combobox"` and `aria-activedescendant`, but the popup is not identified as a `listbox` and result rows are not `option` elements with `aria-selected` ([local markup](../src/client/bookmarks/BookmarksPage.vue#L807-L863)). Aligning the markup with the ARIA combobox pattern would make the already-good keyboard behavior clearer to assistive technology.
4. **Add alternate activation only if it matches actual new-tab use.** `Enter` currently activates the selected result. `Cmd/Ctrl+Enter` opening a Bookmark in a background or new tab could be useful, but it should be validated against the Owner's preferred browsing flow before implementation.
5. **Treat current-Folder scope and typo tolerance as measured follow-ups.** Add a compact scope filter only if global results become noisy with the imported library. Likewise, test fuzzy matching against real queries before enabling it; prefix search is predictable, while loose fuzzy matching can damage ranking.

## Source limitations

External behavior was verified against official help, first-party repositories at fixed commits, and publisher/store listings. PintreeNewTab is third-party relative to Pintree but is the first-party source for its own extension. Pinterest's help documents search behavior inside Pinterest, not a Pinterest new-tab replacement; no official Pinterest new-tab product was identified in the reviewed official sources. Local StarTree links describe the workspace on the research date and may move as the active implementation changes.
